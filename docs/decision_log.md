# Decision Log — CPI Project

## Locked design decisions (from protocol v2)

1. **Outcome scope:** broader inadequate-depth framing (sustained BIS≥60 anywhere in the case), with phase stratification (early/mid/late) as a pre-specified sensitivity analysis — not a narrowed late-case-only emergence window.

2. **Matched negative sampling:** included as a secondary design, but purely as an internal robustness/construct-validity check within the paper. Not framed as a head-to-head comparison against Qian et al.

3. **Nonlinear HR features (DFA, sample entropy):** included in both Model A and Model B.

## Phase 0 decisions

4. **Python version:** 3.13 selected (Windows environment). 3.14 ruled out — CatBoost has no working install path on 3.14 as of testing (confirmed open compatibility issue, no published wheels). 3.13 confirmed compatible with CatBoost (supported since release 1.2.8) and expected compatible with the rest of the stack (LightGBM, miceforest, neurokit2, nolds, vitaldb) based on pre-install research; actual `pip install` served as final confirmation — all libraries installed successfully.

5. **Random seed:** 2311, applied globally wherever randomness is used (splits, class-weighting in place of SMOTE, bootstrap resampling).

6. **imbalanced-learn:** installed per the original Phase 0 library list, but not used in the pipeline — SMOTE was replaced with class-weighting (decision documented separately: linear interpolation between nonlinear HR dynamics features generates physiologically impossible synthetic trajectories).

16. **Phase 4 step 3 complete: LOCF imputation.** Applied to HR, ART_MBP, PLETH_SPO2, ETCO2, BIS on the 3,213-case cohort's 1s-grid interim files. Rule: a run of consecutive missing values is forward-filled only if the entire run is ≤15 seconds (primary cutoff; 10s/30s alternates deferred to Phase 9 sensitivity analysis); longer runs are left entirely as NaN (all-or-nothing per gap, not partial-fill — an interpretive choice since the guide's wording didn't fully specify this, confirmed reasonable). Fill rates: HR 88.6%, ART_MBP 76.9%, SpO2 91.4%, ETCO2 83.2% — high rates expected, since native sampling intervals for these tracks are typically 1-2s, so most "missing" 1-second grid points are normal between-sample gaps, not real data loss. BIS fill rate notably lower (3.9%), consistent with step 2's finding that most BIS missingness comes from long sensor-off/dropout windows (minutes, not seconds) — correctly left unfilled by the ≤15s rule rather than fabricating a flat signal across genuine physiological gaps. EMG and TCI tracks (PPF20_CE, RFTN20_CE) excluded from LOCF — EMG is an artifact-detection signal, TCI tracks are drug-infusion-derived and not treated as physiological monitoring gaps.

18. **Phase 4 step 2 (v3) confirmed: SQI-based filtering validated against EMG-based filtering on this cohort.** SQI distribution (20-case sample, 277,973 valid samples): heavily skewed toward high quality (median 91.7, mean 81.2, IQR 76.9-97.4). SQI<50 flags 9.2% of all samples; SQI<15 flags 7.0% - both far more conservative than EMG>40dB's behavior. Critically, SQI<50 overlapping with BIS>=60 time (the actual test of whether a filter targets artifact vs. genuine signal): only 6.3% of BIS>=60 seconds coincide with SQI<50, vs. 63% for EMG>40dB on the same comparison - a ~10x difference. This confirms SQI-based filtering resolves the EMG/arousal confound: it removes signal-quality artifact without disproportionately deleting genuine inadequate-depth episodes. SQI<50 is locked as the primary threshold; SQI<15 (Huang et al.'s stricter precedent) remains the Phase 9 sensitivity-analysis comparator, as planned.

23. **Phase 5 feature engineering parameters locked.** Window computation stride: 60 seconds (a prediction/feature row computed every 60s of each case, not every second — balances resolution against feature-table size; far finer than the 5/10/15-min horizons). DFA box sizes adapted from Peng et al. (1995) to this study's native 1Hz sampling (Qian et al. 2025/2026 report no explicit, reproducible DFA/entropy parameters — their features came from an automated HCTSA search on 10Hz-resampled data via MATLAB, not a citable fixed parameter set): α1 (short-range) box sizes 4-16s, α2 (long-range) 16-64s, log-spaced, 1st-order detrending. Sample entropy: m=2, r=0.2×SD (per-window SD), per Richman & Moorman (2000) — standard library defaults (neurokit2/nolds). Documented in Methods as standard-literature-convention parameters, not a replication of Qian et al.'s (non-reproducible) exact values.

24. **Hb/Hct decision: Hct dropped from Model A feature set.** VitalDB's clinical data provides `preop_hb` (hemoglobin) but has no `preop_hct` (hematocrit) field. Rather than deriving an approximate Hct from Hb (Hct ≈ Hb×3 rule-of-thumb, which introduces an unverified assumption not necessarily valid across this cohort), Hct is dropped from Model A's feature set; Hb alone is retained, since the two are physiologically highly correlated and Hb likely captures most of the same signal for feature purposes. Documented as a data-availability limitation in Methods/Limitations.

34. **Window-missingness threshold correction: 50%, not 70%, documented as the actual protocol used.** Phase 5's feature engineering used a 50% window-completeness gate (MIN_WINDOW_FRAC), not the originally-specified 30% missingness tolerance (70% completeness) - an unflagged placeholder that was never corrected, discovered during a post-hoc review. Rather than re-run Phases 5-9 (~3-5 hours) to fix this, the actual magnitude was checked first: on a 200-case sample, only 0.98% of window-track observations fall in the disputed 50-70% completeness band (5.10% below 50%, already excluded either way; 93.92% above 70%, kept either way). Given this negligible overlap, 50% is retained as the documented, actual threshold used throughout this project, rather than re-running the full pipeline for a <1% data difference unlikely to materially change results. This decision is reported transparently in Methods, not presented as if 70% was used. Separately noted: the protocol's intended behavior (discarding a failing window entirely) was also not implemented as specified - instead, a failing track's stat becomes NaN and is imputed by MICE rather than the row being dropped. This remains a genuine, if minor, deviation from the written protocol and should be described accurately in Methods rather than glossed over.

### Entry 42 — 2026-09-24 — Matched-sampling secondary design (protocol Section 5.4)

**Rationale:** The primary design draws negatives from all valid windows, which
mixes in windows only minutes away from the next BIS>=60 event alongside
windows far from any event. This secondary design builds a matched negative
set to check whether primary-design performance depends on "easy" negatives.

**Method:** Per case, up to 2 negative windows selected via farthest-point
sampling: >=20 min (1200s) from the start AND end of every event in that
case, and the two picks maximally separated from each other (>=10 min apart)
rather than just both far from the event -- an early version of the selection
function clustered both picks near the same end of the case when the event
sat closer to one side; caught and fixed via a synthetic-data unit test
before running on real data (4 synthetic cases: mid-case event, no events,
case too short for any valid window, two events -- all passed after the fix).
Matched negatives: 5,296 rows across 2,656/2,665 cases. Positives reused
unchanged from the primary design per horizon (14,443 / 26,938 / 38,479 for
5/10/15min). All 6 model/horizon combinations refit with GroupKFold(5) +
IterativeImputer + RobustScaler + SMOTE + LightGBM, reusing each combo's
most-frequent best_params from Phase 7 (no re-tuning, given the much smaller
matched dataset).

**Results (mean AUROC across 5 folds):**
| Model  | Horizon | Primary AUROC | Matched AUROC |
|--------|---------|---------------|----------------|
| ModelA | 5min    | 0.8249        | 0.8819         |
| ModelA | 10min   | 0.8036        | 0.8514         |
| ModelA | 15min   | 0.7883        | 0.8384         |
| ModelB | 5min    | 0.7507        | 0.8616         |
| ModelB | 10min   | 0.7370        | 0.8377         |

Class-separation diagnostic (mean pos-neg difference): HR_mean -0.84 to
-1.07, ART_MBP_mean +1.30 to +3.16, HR_var -11.7 to -16.0, ART_MBP_slope
+0.005 to +0.014 across horizons -- consistent direction and magnitude
across all three horizons.

**Interpretation:** AUROC improves on the matched set for every combination,
in the expected direction -- removing near-event "hard" negatives makes the
classes more separable, without any sign that primary-design performance was
